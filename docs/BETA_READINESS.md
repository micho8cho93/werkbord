# Beta distribution and acceptance

Production admission remains **BLOCKED**. This document is the current operating
policy; dated reports in TEAM_SECURITY_GATE.md remain historical evidence.

## Distribution

The first invitation wave is 3–5 Mac users, using the signed/notarized universal
DMG and the existing preview feed. Team use is limited to disposable evaluation
workspaces and customer-controlled backups. A valid imported Team license enables
the workspace's Team functionality, subject to seats, dates and member/project
permissions. Production admission is a publication/acceptance gate, not a runtime
license switch. Individual remains free and needs no vendor account.

Windows beta downloads are deferred. Building from source remains possible, but
an unsigned EXE, PowerShell or curl command is not a trusted Windows publisher.
Do not advertise a Windows installation workaround or ask users to disable OS
protections.

Linux follows Mac, with one `.deb` for each of amd64 and arm64, initially tested
on Ubuntu 24.04 LTS and Debian 13 with systemd. Debian package versions encode
`4.89.0-preview.1` as `4.89.0~preview.1`; app/executable metadata retains the full
unified version. Desktop beta updates are manual package replacements. AppImage,
RPM, Flatpak, Snap and distribution repositories are deferred. The controller's
shell installer is secondary and opens the browser interface, not the native app.

`LINUX_BETA_ENABLED` defaults off. Enable the repository variable only after
clean-VM package install/start/restart/upgrade/removal acceptance on both target
distributions/architectures. Physical Linux acceptance is additionally required
for production support claims. The workflow's package install/ELF checks alone
do not establish desktop startup or physical-device acceptance.

## Trust and release review

Keep release, Apple and Sparkle keys separate. There is no licence signer any more:
team licensing was removed (see [PLANS.md](PLANS.md)), and the hosted licensing
sections below are kept only as a record of what was inspected before it was.

The unified checksum manifest is signed over UTF-8
`werkbord/release/v1`, NUL, the exact tag, NUL, and the manifest's exact bytes.
Its signature is raw Ed25519 in `checksums.txt.sig`. The candidate includes `release-audit.tar.gz`; the signed manifest binds its exact SBOM/scanner evidence bytes as well as the application artifacts. The legacy Team manifest
domain stays unchanged. A checksum next to an archive cannot authenticate its
publisher. No downloaded executable is run to verify its own authenticity.

Provision `RELEASE_PUBLIC_KEY` (32 bytes, raw URL base64) independently as a public
repository variable and build input. Provision the corresponding PEM to shell
installer users through an independent trusted channel. The default PEM location
is `scripts/keys/werkbord-release.pub`, or set
`WERKBORD_RELEASE_PUBLIC_KEY_FILE` (`DEVBOARD_` spelling also works). No real key
is generated by a build. The owner-provisioned public key and independent
comparison fingerprint are recorded in [scripts/keys/README.md](../scripts/keys/README.md).
Builds without the trust anchor refuse
controller executable updates; Sparkle retains its own existing trust path.

The release workflow first uploads `unsigned-candidate`. Configure the
`release-approval` GitHub environment with required human review and protected tag
rules before allowing releases. Download that workflow run's candidate and review
its source SHA, platform scope, operational evidence and hashes. Sign offline:

```sh
openssl pkey -in /secure/release-private.pkcs8.pem.enc | \
go run ./scripts/release-manifest sign --tag werkbord-vX.Y.Z-preview.N \
  --input /reviewed/candidate/checksums.txt \
  --signature /reviewed/candidate/checksums.txt.sig
openssl base64 -A -in /reviewed/candidate/checksums.txt.sig
```

Enter the encrypted key's passphrase privately at OpenSSL's Terminal prompt;
the decrypted PEM travels directly to the signing command, without a plaintext
key file. Store only that **public signature** as `RELEASE_MANIFEST_SIGNATURE` in the review
environment, then approve the job. The read-only job verifies the signature and
every asset before the separate writer creates a draft. If the run must be retried,
retry the failed review job after setting the signature; rebuilding the candidate
requires a new signature. A stale signature never authorizes different bytes.
No private release key enters CI. Confirm GitHub's required-reviewer settings;
merely naming an environment in YAML does not configure reviewer protection.

Publication still requires explicit owner authorization. Stable builds must pass
both the existing exact-version documentation gate and complete version-specific
`RELEASE_ACCEPTANCE.json` evidence. Never set a requirement to accepted on the
basis of fixtures or an unfinished procedure. Public platform checks precede
latest/feed promotion; previews never become latest. Withdraw a bad feed and ship
a higher fixed version; never replace artifact bytes under an existing tag.

Historical unsigned controller archives are not automatically trusted by the new
updater. Preserve them for manual historical recovery, using independently
verified provenance. Existing `werkbord`/`devboard` aliases and settings remain.

## Soak and privacy-conscious diagnostics

Exercise a fixed workload for 72 hours, then observe the invited group for seven
days before expanding to 10–20 users. Include concurrent agents, schedules,
controller/provider restarts, terminal reconnects, large collections, memory
publication/withdrawal and remote interruptions. Use disposable repositories and
licenses; external provider usage must be explicitly authorized.

Opt in to content-free local observations with:

```sh
python3 scripts/observe-beta.py --pid CONTROLLER_PID \
  --out /private/diagnostics/beta-observations.jsonl
```

The observer records time, HTTP health status, RSS and Linux descriptor counts.
It never reads logs, prompts, repository contents, pairing/license files, keys,
process arguments or environment. Nothing is uploaded. Collect heap/goroutine,
queue, WAL and latency evidence separately on disposable fixtures. The observer
does not create a workload or grant acceptance. Review post-warmup resource growth
over 20%; require a plateau, no corruption, duplicate accepted execution, orphaned
workers/processes or unauthorized actions. Interruptions leave partial receipts.

Team memory is bounded to 10,000 stored revisions, not 10,000 published records.
Revision capacity errors require curator cleanup/compaction, not blind retries.
Local publication journals and backups can retain previously shared text after
withdrawal; withdrawal cannot recall copies already delivered. Review retention
before enabling wider sharing. Indexing, extra caches and UI changes beyond
concrete capacity/error guidance remain deferred until measurements justify them.

Report an incident using the version, OS, failing step and redacted observer
receipt. Do not attach database/full-disk images, raw logs or secrets by default.
